# INIM i2pd fork

This directory contains the INIM-specific patch series against the pinned upstream
`PurpleI2P/i2pd` base (see [DEPENDENCIES.md](../DEPENDENCIES.md)) plus the fork
requirements from the specification (Appendix A).

## Why a fork

Stock `i2pd` gives us `i2cp.leaseSetPrivKey` as **one key per session** — useless for
INIM's per-contact credentials (§7, Appendix A F-1). The fork adds the missing runtime
control surface and hardens I2CP so no other app can reach it.

## Requirements (Appendix A)

| ID | Requirement | Status |
|---|---|---|
| F-1 | Key ring: register client-auth **private** keys per remote Destination, keyed by the **stable blinded identity** `SHA256(stA ‖ A)` (what b33 carries), so lookups match regardless of the daily store hash. | **REWORKED (v3) after Reviewer 2.** Patch `patches/0001-…` + `patches/0003-…` (via `git format-patch`, incremental series): lookup driven by `request->requestedBlindedKey->GetIdentHash()` (new `BlindedPublicKey::GetIdentHash()`), **copies** under the mutex (no raw pointer after unlock), **stack/base64 buffers zeroized** (`lsKey.Fill(0)`, `key.Fill(0)`, base64-by-value scrub always — including when Base64 decoding fails), i2pd-style block layout. **No silent shared-key fallback** when the key ring is in use (fail-closed per-contact mode): the legacy single session key is used only when the ring is empty entirely (`IsKeyRingEmpty`), see [ADR-019](../docs/adr/ADR-019-key-ring-fallback-policy.md). Behavior verification comes with E-1 (right key / wrong key / no key / revoked). |
| F-2/F-3 | Per-client auth lists and padding-to-buckets for the I2CP path are **client side** in v0.9 scope. | **UNCHUNKED after review; not implemented; not done.** Per App. A (v0.9), over I2CP the client (Rust core) builds and signs the Encrypted LeaseSet itself, so per-client auth lists and padding are generated by the core (ADR-018, not yet written; chosen between the two paths after E-1). | F-11 (v0.9, new) | I2CP lookup of a **blinded (b33) destination**: run the encrypted-LeaseSet request with the key ring (F-1) and return the resolved Destination to the session. | **Implemented (patch `patches/0002-…`, `git format-patch`, compiles clean, `git am` applies after 0001 on clean 2.61.0).** `HostLookupMessageHandler` `case 1` now branches: ident-hash addresses as before; blinded addresses go through `RequestDestinationWithEncryptedLeaseSet` with the (blinded) address's `BlindedPublicKey`, replying `HostReply` with the resolved identity once the LeaseSet arrives (the per-remote auth key is picked up from the F-1 key ring during decryption; without a key the request ends as a null `HostReply`). Re-resolution across the daily blinded-key rotation works automatically because the ring identity `SHA256(stA‖A)` is date-independent. **Runtime behavior not yet exercised:** needs F-4/E-1 verification (right key / wrong key / no key) |
| F-4 | Router-level allowlist **keyed by the contact's ECIES-X25519 static public key(s)** (all enc types the profile uses), enforced in the New Session handler right after the sender static key is known and **before** any clove/payload reaches the app. Zero static key (anonymous new session) = dropped by default. A revocation also closes existing sessions and tag sets for that peer. | pending (v0.9 wording). Note: ContactCard and Enrollment must carry the contact's ECIES static keys in addition to `dest_b33` (spec §6.5 as amended) |
| F-5 | Router events delivered over the **separate control channel** (F-8): tunnel readiness, LeaseSet published/confirmed, client key added/removed, peer connect/drop, auth failure counters. Length-prefixed **CBOR**, versioned schema; no ad-hoc I2CP extension types. | pending (v0.9 wording) |

## Layout

- `patches/` — one patch per fork feature, applied in order on the pinned base.
- `UPSTREAM.md` — pinned base tag/commit, rebase instructions, patch ordering.

## Building (base + patches)

On the pinned base tag, apply patches with `git am` (same as CI) and build — or just run
`scripts/apply-patches.sh` from inside the clean checkout:

```bash
git clone https://github.com/PurpleI2P/i2pd.git
cd i2pd
git checkout 2.61.0                  # pinned tag, see UPSTREAM.md
../i2pd-fork/scripts/apply-patches.sh   # sequential git am
make -j$(nproc)
```

Targets are unchanged from upstream (`i2pd`, client/lang libs); on Android the patch
series additionally builds a JNI library (F-10, later).
